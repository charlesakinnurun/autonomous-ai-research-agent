# ADR-0004: Evidence-First Claims and Claim-Level Citations

- **Status:** Accepted
- **Date:** 2026-11-07
- **Phase:** 0 (implemented in Phase 4)
- **Deciders:** Project owner

## Context

A cited report can still be wrong in three ways:

1. The cited URL does not contain the claim (bad citation).
2. The URL is fabricated or unreachable.
3. The claim is true but unsupported by the cited span (lucky guess).

A document-level "sources" list does not catch any of these. We need claim-level tracking from draft to final report, with a verifier verdict and a persisted evidence span.

## Decision

Adopt an **evidence-first claim model**:

- Sources are fetched and assigned stable IDs before writing.
- The writer may cite only fetched source IDs; it cannot emit arbitrary URLs.
- The draft is decomposed into atomic claims, each with inline markers `[S1]`.
- The verifier checks each claim against its **cited span**, not the open web.
- Verdicts are `supported`, `contradicted`, or `insufficient`, with a quote and rationale.
- Kept claims require a `supported` verdict and ≥1 citation.
- Unsupported claims are removed from the main body; if retained for transparency, they go to a labeled "Unverified claims" appendix.
- Contradictions are preserved; contested topics report positions, not forced consensus.
- The renderer validates every marker and every URL before returning the report.

Persistence:

```text
claims -> claim_evidence -> chunks -> documents -> sources
claims -> citations -> sources/chunks
```

## Consequences

**Positive**

- Citation precision/recall become measurable, not aspirational.
- Fabricated URLs are structurally impossible in the final report.
- Reviewers can inspect claim → quote → source.
- Supports honest "insufficient evidence" outcomes.
- Enables per-claim judge calibration.

**Negative**

- More LLM calls (claim extraction + verification).
- Verification can be wrong; self-verification is not ground truth.
- Atomic claim extraction is noisy and can fragment the narrative.
- Contradiction search adds cost.

**Mitigations**

- Batch verification calls.
- Calibrate the verifier against human labels.
- Keep claims at sentence/clause granularity, not phrase-level.
- Use judge audits and report verifier accuracy.

## Alternatives considered

| Alternative | Why rejected |
|---|---|
| Document-level citations only | Cannot detect bad citations or unsupported claims |
| Footnote URLs generated by the writer | Hallucination risk; no provenance guarantee |
| Post-hoc URL check only | Checks reachability, not entailment |
| Human review of every claim | Not automatable at benchmark scale |
| Trust the writer's self-citations | Unreliable; defeats the purpose |

## Verification

- Renderer rejects dangling markers and invented URLs.
- Unsupported-claim removal test.
- Conflicting-source test.
- Eval: citation precision/recall, URL validity, groundedness.
- Human calibration of the verifier.
